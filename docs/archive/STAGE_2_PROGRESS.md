## 1. 구현한 사용자 흐름

1. 오른쪽 ‘사진 적용’에서 편집창을 연다. 기본 캐릭터로 바로 플레이할 수도 있다.
2. JPEG·PNG·WebP 사진을 선택하고 원형으로 자르거나 얼굴 윤곽을 직접 그린다.
3. 얼굴을 찾으면 눈·코·얼굴 윤곽의 기준점을 표시하고 초기 위치·크기·기울기를 맞춘다. 최대 4개까지 검출하며 여러 얼굴은 직접 선택한다.
4. 드래그·방향키 또는 위치·확대·회전 슬라이더로 보정한다. 좌우 반전과 편집 초기화도 제공한다.
5. 선택한 원형 또는 직접 그린 윤곽 안쪽만 적용한다. 영역 바깥은 투명하며 흰색 배경이나 만화 눈·입을 합성하지 않는다. 직접 그린 윤곽에서는 둥근 머리 바탕을 숨긴다.
6. 특징점이 있으면 기본 사진과 변형 사진 2장을 준비한다. 충격 조건을 만족할 때 사진을 교체하고 반창고·멍·상처를 별도로 표시한다.
7. 재배치하면 선택 사진·편집값·준비한 변형 사진을 유지한다. 새로고침하면 기본 캐릭터로 시작한다.

검출 실패·모델 로딩 실패 시 수동으로 잘라 적용할 수 있다. 분석이 오래 걸리면 ‘분석을 기다리지 않고 직접 맞추기’를 선택할 수 있으며, 뒤늦게 도착한 결과가 수동 편집을 덮어쓰지 않는다. 특징점 없는 사진은 변형 없이 기본 사진과 상처 부착을 사용한다.

## 2. 시제품의 초기값과 동작

사진 2배·일그러짐 1.8배·멍/상처/반창고 각각 1.5배는 2026-11-09 사용자 확정값이다. 실험 노트의 해당 조절 바는 제거했다. 그 외 충격 기준·초기화 규칙은 시제품 기본값으로 구분한다.

| 항목 | 구현값 |
| --- | --- |
| 마스크 | 원형(반지름 47%) 또는 사용자가 직접 그린 닫힌 윤곽. 윤곽 사진에서는 머리 바탕·외곽선을 숨김 |
| 사진 표시·충돌 | 기준 72px × 고정 2배 = 144px. 실험 노트에는 값만 표시. 충돌·잡기는 기존 머리 도형만 사용 |
| 자국 크기 | 멍·상처·반창고 각각 1.5배 고정. 해당 조절 바 제거 |
| 얼굴 텍스처 | 512×512 Canvas, 투명도 보존. GPU 텍스처 1개를 재사용 |
| 입력 제한 | JPEG·PNG·WebP, 20MB·4천만 화소 이하 |
| 편집 기준 이미지 | 방향을 정규화하고 최대 변 길이 4096px로 제한. 재편집은 이 이미지에서 시작 |
| 분석 입력 | 최대 변 길이 1024px. 결과 좌표를 편집 기준 이미지로 환산 |
| 검출 | `@mediapipe/tasks-vision` 1.2.2 / Face Landmarker float16 v1 / IMAGE / CPU |
| 변형 | 입과 각 눈의 양끝을 중심 기준 아래로 휘는 변형 2장. 단계별 강도 1 / 1.7 |
| 일그러짐 강도 | 1.8배 고정. 조절 바 제거. 적용 시 기본 사진에서 변형 2장 생성 |
| 사진 교체 | 머리에 인정된 충격 3회에 1단계, 6회에 2단계. 이후 2단계 유지 |
| 실제 충격 | 벽·바닥 접촉의 법선 접근 속력 220px/s 이상. 신체끼리의 접촉은 제외 |
| 중복 제한 | 동일 부위의 실제 충격 간격 450ms. 한 렌더 프레임의 부위별 가장 강한 충격만 사용 |
| 상처 | 멍 → 상처 → 반창고 순환 선택. 전체 최대 100개, 오래된 것부터 교체 |
| 상처 위치·경계 | 테두리를 포함한 부위 전체에서 중심을 균일하게 선택. 사진은 불투명 픽셀 전체 사용. 자국 크기 때문에 가장자리를 제외하거나 자동 축소하지 않음 |
| 재배치 | 사진 유지, 상처·누적 충격 제거, 기본 사진 단계 복귀 |
| 재편집 적용·사진 교체·기본 얼굴 복귀 | 상처·누적 충격 초기화 |

오른쪽 ‘충격에 따른 변화 미리보기’는 실제 힘 없이 선택한 부위의 외형 변경 경로를 확인한다. 사용자의 명시적인 미리보기 클릭은 실제 충돌 중복 제한을 우회한다. 무기·점수 기능은 만들지 않았다. ‘상처 지우기’는 상처·누적 충격·변형 단계를 함께 초기화한다.

## 3. 기술 구현

- 사진 원본 파일을 전송하거나 브라우저 저장소에 기록하지 않는다. 편집 이미지·특징점·변형 사진은 현재 문서의 메모리에 둔다.
- MediaPipe JS·WASM은 npm 의존성에서 Vite가 빌드에 포함하고, 모델은 `public/models/face_landmarker.task`에서 제공한다. 얼굴 분석 라이브러리는 사진 선택 시 지연 로딩한다.
- 현재 분석은 게임이 멈춘 편집창에서 한 번의 동기 추론으로 실행한다. 입력을 1024px로 제한했으며 Worker 분리는 아직 하지 않았다.
- 사진과 기준점에 동일한 이동·회전·크기·반전 변환을 적용한다. 부착 뒤에는 최종 머리 위치·각도만 추종한다.
- 변형은 입꼬리 61·291, 각 눈의 양끝 33·133 / 362·263 사이의 중심점을 각각 고정하고 양끝을 턱 방향으로 내린다. 얼굴 편집 후 좌표를 사용해 회전·좌우 반전에서도 얼굴의 아래 방향을 따른다. 이동량은 해당 부위 폭의 14% × 단계 강도(1 / 1.7) × 고정 강도 1.8이며, 중심과 주변으로 갈수록 변형을 줄인다. 코를 옆으로 밀거나 한쪽 입꼬리를 올리던 변형을 교체했다. 편집창의 기준점 표시가 켜져 있으면 중심 3개를 노란색으로 보여주며 적용 사진에는 점을 그리지 않는다.
- 과거 실험용 강도 슬라이더와 변경 후 사진 재생성·지연 처리 경로를 제거했다. 강도는 1.8배로 고정하고 원본·편집값·동일 마스크로 적용 시 변형을 생성한다. 특징점이 없는 사진은 변형을 생략한다.
- 변형 사진은 같은 기본 이미지에서 역방향 픽셀 샘플링으로 생성하고 동일한 원형 또는 사용자 윤곽 마스크를 적용한다. 기본·변형 사진의 알파 합성도 통일해 교체 시 테두리를 유지한다. 생성 중에는 이벤트 루프에 제어를 돌려 취소·재선택을 처리한다.
- 상처는 별도 투명 SVG 검증 에셋이다. 일정 속력 이상의 충격을 인정한 뒤 충돌한 부위 내부에서 무작위 로컬 좌표를 선택하고 이후 이동·회전에 맞춰 표시한다. 접촉점을 그대로 사용해 관절·신체 끝에만 몰리던 표시를 수정했다. 사진 교체가 상처를 지우지 않는다.
- 기본 머리는 테두리를 포함한 원 전체를 균일하게 샘플링하고 팔다리·몸통은 표시 다각형을 삼각형으로 나눠 면적 비율로 선택한다. 자국의 크기·회전을 위한 내부 여백을 없애 테두리 근처도 선택하며 이미지 일부의 돌출을 허용한다. 사진은 원형·사용자 윤곽 모두 알파 128 이상 픽셀을 캐시해 균일하게 고른다. 좁은 사진에서도 자국을 자동 축소하지 않는다. 속력 220px/s·450ms 반복 제한을 유지하고 상한은 100개로 늘렸다.
- `appearanceConfig.ts`의 중첩된 읽기 전용 `FIXED_APPEARANCE`에 사진 2배·일그러짐 1.8배·자국 종류별 1.5배를 모았다. 런타임 배율 변경 경로를 제거하고 실험 노트에는 확정값만 표시한다. 사진 배율은 표시 이미지만 바꾸므로 머리의 질량·관성·충돌·잡기 범위를 확대하지 않는다.
- 물리 엔진 접촉과 기존 수동 방 경계 보정을 함께 관찰한다. 관절 정렬·기립·재배치의 자세 보정은 충격에서 제외한다. 신체·관절·기존 물리 수치를 추가하거나 바꾸지 않았다.
- 편집창의 일시정지 사유를 분리하고 창 비활성화로 멈춘 게임은 편집 종료만으로 재개하지 않는다. 편집 중 게임 단축키는 차단한다.
- 작은 미리보기는 게임 캔버스의 현재 표시 배율을 반영한다. 게임 캔버스용 CSS가 편집 캔버스에 영향을 주지 않도록 범위를 제한했다.
- 기존 `angularStiffness` 옵션의 Phaser 내장 Matter 타입 누락을 `matter.ts`에서 보완했다. 잡기 런타임 동작은 변경하지 않았다.

### 사용자 윤곽 편집 추가

- 사진 선택 후 ‘직접 윤곽 그리기’에서 테두리를 클릭하거나 드래그한다. 시작점을 다시 누르거나 ‘윤곽 완성’·Enter로 닫는다. 자유 선은 시작점 근처로 돌아와 놓아도 완성된다.
- 윤곽 완성 시 종횡비·방향을 유지해 머리 크기에 맞춘다. ‘윤곽에 맞추기’로 다시 맞출 수 있다.
- ‘점 수정’에서 점을 드래그한다. `[` / `]`로 점을 선택하고 방향키로 이동하며 Delete로 삭제할 수 있다. 닫힌 윤곽에는 최소 3개 점을 유지한다.
- 윤곽 실행 취소는 최대 40회, 점은 최대 256개로 제한한다. 드래그의 중복 샘플을 정리해 점 개수를 줄인다.
- 선택 사항인 ‘윤곽 부드럽게 하기’는 모서리를 곡선으로 연결하며, 실행 취소로 이전 모양을 복구할 수 있다.
- 열린 선·교차한 선·너무 좁은 영역은 적용하지 않는다. ‘다시 그리기’로 새로 그리거나 점을 이동해 수정한다.
- 윤곽은 원본 이미지 좌표로 보관하므로 사진 이동·확대·회전·반전과 함께 움직인다. 점을 움직일 때 화면 배율과 사진 변환의 역변환을 적용한다.
- 재편집 취소는 이전 윤곽을 보존하고, 새 사진 선택은 원형과 빈 윤곽으로 시작한다. 같은 사진에서 원형·윤곽 모드를 전환할 때 그린 점을 유지한다.
- 직접 그린 사진의 머리 바탕만 숨기고 기존 원형 물리·관절·잡기 판정은 유지한다. 사진과 윤곽은 재배치 후에도 유지한다.

자동 시나리오는 수동 적용·마스크 투명도·재배치 유지·새로고침 해제·변형 교체·상처 유지·회전 추종·기존 설정 유지·정지 사유·분석 취소·다중 얼굴 선택·잘못된 파일·모델 실패·반복 교체의 개수 상한·실제 방 충돌·약한/중복 접촉 무시·좁은 화면을 확인한다.

윤곽 편집에 대해 5개 시나리오를 추가했다. 점/드래그 입력·시작점으로 닫기·점 이동/삭제/실행 취소·부드럽게 하기·교차한 선 차단/수정·사진 반전/회전·좁은 화면·재편집 취소·재배치 유지·사진 교체 초기화를 확인했다. 기본 사진과 변형 사진의 전체 알파 픽셀 값이 일치하는지도 검사한다. 실제 얼굴 사진에서도 개발 서버에서 직접 그린 윤곽 적용·머리 바탕 숨김·변형 2장 준비를 확인했다.

윤곽 기능을 포함한 빌드 결과는 Canvas 렌더러에서도 실제 얼굴 사진의 검출·직접 그린 윤곽 적용·변형 사진 교체·재배치 후 윤곽 유지가 동작했고, 해당 흐름의 브라우저 실행 오류는 없었다.

상처의 무작위 위치 변경에는 고정 난수열을 이용한 검사 2개를 추가했다. 머리·몸통·팔·다리의 가운데와 양쪽으로 위치가 분산되는지, 좁은 사용자 윤곽 사진에서도 상처 중심이 불투명 픽셀에 놓이고 자동 축소 없이 회전을 따라가는지 확인한다.

2026-11-08에는 실제 얼굴 사진으로 기본 2배 표시·변형 2장·자국 부착 및 당시 실험용 슬라이더를 확인했다. 강도 0~2배 조절·원본 재생성·연속 조절 취소를 포함한 당시 26개 검사는 이력이며, 아래 현재 고정값 검증과 구분한다.

2026-11-09 사용자 확정으로 사진 2배·일그러짐 1.8배·자국 종류별 1.5배를 적용하고 조절 바·이벤트 처리·설정 변경·재생성 전용 경로를 제거했다. 기존 편집창의 위치·확대·회전·윤곽 편집은 유지한다. 현재 사진 검사 24개를 통과했다.

현재 검사는 외형 입력 바가 없는지와 고정값 표시, 사진 적용 전후 머리 물리 도형 유지, 사진 돌출 영역 잡기 제외, 재배치·미리보기의 2배 유지, 머리·팔의 세 자국 종류별 1.5배 크기를 확인한다. 고정 1.8배 일그러짐은 색상 표식의 실제 픽셀 중심을 측정해 입·두 눈의 양끝 처짐, 중심 유지, 회전·좌우 반전 방향, 동일 마스크를 검사한다. 부위 전체의 무작위 분포와 100개 상한도 유지한다.

얼굴 검출 성공·다중 얼굴·지연에 관한 자동 UI 시나리오는 고정 특징점을 주입해 재현성을 확보한다. 실제 MediaPipe 검출은 별도의 브라우저 확인으로 보완했다. 실제 검출에 사용한 [MediaPipe 제공 사진](https://storage.googleapis.com/mediapipe-assets/portrait.jpg)은 임시 경로에만 내려받아 사용했고 저장소에는 추가하지 않았다.

빌드 미리보기에서 실제 사진 1장으로 측정한 한 번의 예시는 선택 후 검출 완료 약 479ms, 적용 버튼 후 변형 준비·편집창 종료 약 409ms였다. 같은 호스트에서 정적 파일을 제공한 결과이며 다른 PC·네트워크의 성능 보장은 아니다. 일반 플레이의 장시간 FPS와 최대 입력 크기의 메모리는 추가 측정 대상이다.

기존 실험 1의 물리 테스트 전체는 현재 기본값과 기대값이 맞지 않는 항목이 있어 이번에 실행·갱신하지 않았다. 2단계 검사 통과를 기존 물리 전체 시나리오의 통과로 해석하지 않는다.

## 5. 남은 확인 사항

- 원형/사용자 윤곽·여백·실제 얼굴 가독성의 사용자 평가와 256/512px 비교.
- 고정 1.8배의 입·눈 변형 외형 평가. 추가 변형 장수는 후속 요구가 있을 때 검토.
- 머리만 또는 전신 충격을 사진 교체에 사용할지, 횟수·누적 강도 중 기준 선택.
- 재배치 시 상처·변형 단계 초기화라는 시제품 기본값의 최종 확정.
- 최종 투명 배경 반창고·멍·상처 에셋 교체와 100개 누적·테두리 돌출 상태의 외형 평가.
- 여러 PC·Chrome/Edge/Firefox와 실제 사용자 사진들의 검출 성공률·EXIF 방향 사례 확인.
- 대형 사진·반복 사용의 장시간 메모리·FPS와 모델 첫 로딩 시간 확인. WASM은 약 14.6MB, 모델은 약 3.76MB이며 사진 선택 시 로드한다.
- 무기·소리·점수·회복 연출은 기존 후속 단계에서 구현.

구현은 현재 로컬 시제품까지이며 공개 배포하지 않았다.
