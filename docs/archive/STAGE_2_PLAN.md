## 1. 사용자 확정 사항

| 항목 | 확정 내용 |
| --- | --- |
| 사진 적용 범위 | 하얀색 원형 마스크 또는 사용자가 직접 그린 닫힌 얼굴 윤곽의 내부 영역만 사용한다. 후속 사용자 요청으로 직접 윤곽 그리기를 추가했다. |
| 적용 대상 | 잘라낸 사진을 기존 래그돌의 얼굴 도형 위에 적용한다. |
| 사진 크기·충돌 | 사진은 2배로 고정한다. 조절 바를 제거하며, 도형 밖으로 나온 부분은 충돌·잡기 판정에 포함하지 않는다. |
| 자국 크기·개수 | 멍·상처·반창고 배율은 각각 1.5배로 고정하고 조절 바를 제거한다. 최대 100개를 유지하고 오래된 것부터 교체한다. |
| 자국 위치 | 충돌한 부위의 테두리를 포함한 전체 표면에서 중심을 무작위로 고른다. 자국 크기 때문에 가장자리 배치를 제외하거나 자동 축소하지 않는다. |
| 사진 품질 | 작은 얼굴에서도 알아보기 쉽도록 고화질을 우선하여 압축·크기 최적화한다. |
| 표정 덧붙이기 | 사진 위에 별도의 만화 눈·입이나 표정 이미지를 덧붙이지 않는다. |
| 일그러짐 강도 | 입·눈의 처짐 강도를 1.8배로 고정하고 조절 바를 제거한다. 기본/변형 사진은 적용 시 원본에서 생성한다. |
| 사진 변형 | MediaPipe 특징점으로 입과 각 눈의 양끝 사이 중심을 고정하고 양끝이 아래로 처지게 변형한 사진을 생성·보관한다. 피격이 누적될수록 강한 단계로 교체한다. |
| 기본 피격 표현 | 투명 배경의 반창고·멍·상처 에셋을 충격에 따라 얼굴 또는 몸에 적용한다. 사진 변형과 별도의 레이어로 관리한다. |
| 재배치 | 적용한 사진을 유지한다. |
| 새로고침 | 사진 적용을 해제하고 기본 캐릭터로 시작한다. |

2026-11-05에 제외했던 얼굴 변형의 범위는 이번 요구로 갱신한다. **특징점을 이용해 변형 사진을 미리 생성하고 충격에 따라 교체하는 방식은 포함**한다. 사용자가 플레이 중 얼굴을 직접 잡아 늘이는 조작은 포함하지 않는다.

이 문서에서 사진을 ‘저장’한다는 표현은 현재 페이지의 메모리에 보관한다는 뜻이다. 원본·특징점·편집값·변형 사진을 localStorage, sessionStorage, IndexedDB, 서버 등에 영구 보관하지 않는다. 모델·기본 에셋 파일의 캐시와 사용자 사진의 보관은 구분한다.

## 2. 2단계 범위와 후속 단계의 경계

### 이번 단계에서 구현·검증할 것

- 사진 선택, 방향 보정, 작업용 이미지 준비와 파일 오류 안내.
- 하얀색 적용 마스크와 위치·크기·회전 수동 보정 UI.
- 얼굴 특징점 검출과 편집 결과에 맞춘 좌표 변환.
- 마스크 내부 사진 생성, 머리 부착, 이동·회전·재배치 추종.
- 기본 사진과 소수의 변형 사진을 생성·보관하고 교체하는 최소 경로.
- 투명 배경 상처 에셋을 얼굴·몸의 충격 위치에 붙이는 최소 경로.
- 검증용 충격 입력 또는 기존 벽·바닥 충돌을 통한 사진 교체·에셋 부착 확인.
- 사진 교체·취소·기본 얼굴 복귀, 재배치 유지·새로고침 해제 및 자원 정리.

### 후속 단계에서 완성할 것

- 3단계: 무기 3종의 실제 명중 이벤트, 효과음, 충격 강도와 외형 변화의 본격 연동.
- 4단계: 최종 상처 에셋, 변형 단계의 종류·강도, 누적 외형 변화와 회복 연출의 완성.
- 점수·콤보·해금·공개 배포·모바일 확장은 기존 단계대로 진행한다.

2단계에서도 변형 사진 교체와 상처 부착의 최소 동작은 확인한다. 최종 무기나 다수의 완성 에셋이 없어도 검증할 수 있도록 하되, 검증용 입력은 실제 공격 기능과 구분한다. 효과음 제작은 이번 단계의 필수 완료 조건에 넣지 않는다.

## 3. 사용자 흐름

1. 기본 캐릭터로 시작한다. 사진 없이도 플레이할 수 있다.
2. 사진 적용 버튼을 누르면 잡기를 해제하고 게임을 일시정지한 뒤 사진 선택·편집 창을 연다.
3. 사진을 선택하면 방향과 크기를 정리하고 얼굴 특징점을 분석한다. 분석·모델 준비 상태를 표시한다.
4. 하얀색 마스크가 적용 범위를 안내한다. 사진을 이동·확대·축소·회전해 마스크에 맞추고, 큰 편집 미리보기와 게임 속 실제 표시 크기를 함께 확인한다.
5. 적용하면 동일한 마스크와 변환값으로 사진을 잘라 머리 위에 표시한다. 변형 사진 준비 상태를 표시하며 기본 사진부터 사용할 수 있게 한다.
6. 유효한 충격이 발생하면 상처 에셋을 붙이고, 정한 조건을 만족할 때 준비된 변형 사진으로 교체한다.
7. 재편집·사진 교체·기본 얼굴 복귀를 제공한다. 취소하면 이전에 적용했던 사진과 편집 상태를 유지한다.
8. 재배치하면 사진을 새 머리에 다시 연결한다. 새로고침하면 사진을 복원하지 않는다.

편집창을 열기 전의 일시정지 상태를 보관한다. 편집 종료만으로 기존 수동 정지나 창 비활성화에 따른 정지를 해제하지 않는다. 파일 선택 취소·모델 실패·편집 취소에도 입력 상태가 남지 않도록 한다.

## 4. 하얀색 마스크와 사진 품질

### 4.1 마스크의 의미

- 하얀색은 편집 화면에서 적용 범위를 알리는 표시이다. 최종 사진에 흰색 판을 합성하는 의미로 사용하지 않는다.
- 마스크 안쪽 사진만 남기고 바깥쪽은 투명하게 처리한다. 편집 미리보기와 실제 출력에 같은 마스크 데이터를 사용한다.
- 결과 사진을 기존 얼굴 도형 위에 겹쳐 표시한다. 사진이 없는 투명 영역에는 기존 머리 바탕이 보일 수 있다.
- 사진의 종횡비를 억지로 바꾸지 않고 이동·동일 비율 확대·축소·회전으로 맞춘다.
- 원형 모드와 사용자가 직접 윤곽을 그리는 모드를 제공한다. 직접 윤곽에서는 점/드래그 입력·점 수정·실행 취소·곡선 보정을 지원하고 기존 머리 바탕을 숨긴다. 사용자 윤곽은 사진에 연결해 위치·크기·회전·반전을 함께 적용한다.
- 변형 사진도 같은 출력 크기·중심·마스크를 사용한다. 교체 순간 얼굴 전체가 튀거나 마스크 밖으로 새지 않게 한다.

### 4.2 고화질 압축·크기 최적화

사진 배율의 기준 크기는 게임 좌표 72px이며 2배인 144px로 고정한다. 기존 머리 충돌 도형은 그대로 두고 실험 노트에는 값을 표시한다. 파일 압축률, 이미지 픽셀 수, 화면 표시 크기는 별도로 관리한다. 작은 파일만을 목표로 얼굴을 72×72로 조기에 축소하지 않는다.

- 원본은 편집의 기준으로 보관하고 반복 압축한 결과를 다시 편집 원본으로 쓰지 않는다.
- 이미지 방향을 먼저 정리한다. 큰 원본의 분석용 축소와 최종 얼굴 출력용 잘라내기를 분리해 불필요한 화질 저하를 줄인다.
- 분석용 이미지에서 얻은 특징점은 원본 기준 좌표로 환산할 수 있게 축소 배율을 보관한다.
- 최종 얼굴 텍스처는 256×256과 512×512를 초기 비교안으로 삼는다. 512×512부터 실제 얼굴 가독성과 메모리를 확인한 뒤 최종 값을 정한다.
- 마스크 바깥의 투명도를 보존한다. 초기 검증은 무손실 PNG 또는 Canvas 기반 텍스처를 사용하고, 고품질 WebP 등은 실제 비교 후 선택한다.
- 압축된 파일 크기가 작아도 디코딩 후 이미지와 GPU 텍스처의 메모리는 별도로 발생한다. 원본 크기·변형 수·해상도에 상한을 둔다.
- 얼굴이 너무 작거나 흐린 원본은 고해상도 출력만으로 세부 정보를 복구할 수 없다. 편집창에서 이를 확인할 수 있게 한다.

해상도·파일 크기 제한·압축 설정은 시제품 비교 후 확정하며, 위 제안 수치를 사용자 확정값으로 사용하지 않는다.

## 5. 특징점과 사진 편집·변형

### 5.1 특징점 분석

- 후보는 기획서의 MediaPipe Face Landmarker이며, 정확한 패키지 버전·모델·실행 방식은 구현 착수 시 호환성을 확인해 고정한다.
- 사진 선택·교체 시 분석하고 결과를 재사용한다. 게임의 매 프레임·매 충격마다 재분석하지 않는다.
- 위치·크기·회전·반전·자르기 변환을 사진과 특징점에 동일하게 적용한다.
- 좌표계는 `방향 보정된 원본 → 편집·마스크 출력 → 머리 로컬 → 게임 월드`로 구분한다. 분석용 축소 좌표와 화면 CSS 좌표를 직접 혼용하지 않는다.
- 분석 작업은 게임 물리 루프와 분리한다. 필요하면 Worker를 검토하고, 새 사진 선택 시 이전 요청의 결과를 적용하지 않도록 요청 식별자를 둔다.

### 5.2 변형 사진 생성·교체

특징점 검출은 좌표를 얻는 역할이고, 사진을 실제로 일그러뜨리는 것은 별도 편집 모듈의 역할이다.

1. 적용 확정 시 기본 사진과 편집 후 특징점을 준비한다.
2. 대상 특징점·이동 방향·영향 반경·변형 강도를 가진 변형 설정으로 사진을 생성한다.
3. 각 변형은 같은 기본 사진에서 생성한다. 이전 변형을 다시 변형해 화질 저하와 좌표 오차를 누적하지 않는다.
4. 변형 뒤 동일한 마스크를 적용하고 기본 사진과 같은 크기·중심으로 메모리에 보관한다. 경계의 빈틈·찢어짐을 확인한다.
5. 충격 조건을 만족하면 준비된 사진으로 교체한다. 충격마다 무거운 이미지 생성 작업을 실행하지 않는다.
6. 사진을 재편집·교체하면 이전 특징점·변형 사진을 무효화하고 새 결과로 교체한다.

현재 기본 1장과 변형 2장을 사용한다. 사용자 참고 이미지에 따라 입·각 눈의 중심을 고정하고 양끝을 얼굴의 아래 방향으로 휜다. 머리 충격 3회·6회에 단계 강도 1·1.7배로 교체하며 고정 강도 1.8배를 함께 곱한다. 실험 노트의 강도 조절 기능은 제거하고 사진 적용 시 원본에서 변형을 생성한다. 편집창의 기준점 표시에는 중심 3개를 추가하되 적용 사진에는 점을 그리지 않는다. 전체 강도 1.8배는 확정값이며 추가 변형 장수는 후속 요구가 있을 때 검토한다. 사진 위에 별도의 눈·입·표정 그림을 덧붙이지 않으며, 사진 사용 중 기존 도형 얼굴의 눈·입도 숨긴다.

### 5.3 실패 처리

- 얼굴을 못 찾으면 재선택·수동 자르기·기본 캐릭터 선택을 제공하는 안으로 진행한다.
- 수동 자르기로 기본 사진을 적용한 경우 특징점 기반 변형은 비활성화한다. 특징점 없이도 반창고·멍·상처 부착은 사용할 수 있게 한다.
- 여러 얼굴을 검출했을 때는 적용할 얼굴을 고르는 방식을 제안한다. 자동으로 임의의 얼굴을 확정하지 않는다.
- 변형 생성이 실패해도 기본 사진을 유지하며 플레이를 막지 않는다.
- 지원 파일 형식과 모델 로딩 실패를 얼굴 검출 실패와 구분해 안내한다.

## 6. 충격에 따른 사진 교체와 상처 에셋

### 6.1 공통 충격 정보

공격·벽·바닥 충돌에서 사용할 정보로 부위, 충격 위치, 방향, 강도, 발생 시각을 준비한다. 사진 교체와 상처 부착이 같은 판정 정보를 사용하도록 한다.

- ‘일정 충격’이 횟수인지 단일 강도인지 누적 강도인지는 아직 미정이다. 판정 조건을 데이터로 분리한다.
- 어떤 충격이 얼굴 사진 교체에 영향을 주는지 구분한다. 얼굴 충격만 사용할지 전신 충격을 포함할지는 미정이다.
- 미세한 접촉·정지 떨림·한 번의 충돌에서 생기는 반복 하위 스텝을 별도 피격으로 누적하지 않는다.
- 물리 엔진 충돌과 수동 경계 보정이 같은 충격을 중복 보고하거나 누락하지 않는지 확인한다.
- 관절 정렬·기립·재배치 등 시스템의 자세 보정 자체를 공격으로 세지 않는다.
- 2단계 검증용 입력과 3단계 실제 명중이 같은 외형 변경 경로를 사용하게 한다.

### 6.2 투명 배경 에셋

- 반창고·멍·상처를 알파 채널이 있는 별도 이미지로 관리하고 얼굴 또는 몸의 해당 부위 위에 표시한다.
- 일정 이상의 속력으로 충돌하면 맞은 부위 내부의 무작위 로컬 위치에 상처를 표시한다. 이후 부위가 회전하거나 이동해도 선택한 자리에 붙인다. 접촉 위치는 충격 정보로 유지하되 상처가 관절·끝부분에만 몰리는 배치에는 사용하지 않는다.
- 기본 머리 바탕 → 기본/변형 사진 → 상처 에셋 → 개발용 디버그 표시 순서로 구성한다.
- 상처 에셋을 사진에 매번 합성하지 않는다. 사진 교체가 기존 상처를 지우지 않게 한다.
- 자국 중심은 테두리를 포함한 표면 전체에서 선택한다. 사진은 불투명 픽셀 전체를 사용한다. 이미지 일부의 돌출을 허용하며 크기에 따라 위치를 제한하거나 자동 축소하지 않는다.
- 최대 100개를 유지하고 초과 시 오래된 것부터 교체한다. 멍·상처·반창고 크기는 각각 1.5배로 고정한다. 사진 위 자국은 정규화 좌표로 보관해 같은 사진 위치를 유지한다.
- 최종 에셋 확보 전에는 검증용 투명 배경 에셋으로 위치·회전·누적 경로를 확인한다.

변형 사진 위에서도 상처는 신체 로컬 위치를 유지하는 것을 초기 제안으로 둔다. 피부 변형을 따라 상처 위치까지 이동시키는 기능은 별도 필요 여부를 정한다.

## 7. 머리 결합 및 사진의 수명주기

- 사진은 추가 물리 물체로 만들지 않고 표시용 이미지로 둔다. 기존 머리 질량·충돌 모양·관절·물리 확정값을 유지한다.
- 한 프레임의 모든 물리·관절·기립 보정이 끝난 머리 위치·각도로 사진을 갱신한다.
- 원본·편집값·기본/변형 사진은 인형 객체와 별도로 관리한다. `PhysicsScene.reset()`이 인형을 새로 만들어도 현재 사진을 새 머리에 다시 연결한다.
- 사진 교체는 새 결과가 준비된 뒤 적용한다. 실패·취소 시 기존 사진을 유지한다.
- 새 결과가 더 이상 참조하지 않는 이전 텍스처·이미지·Object URL·분석 자원을 해제한다. 늦게 끝난 이전 작업도 해제 대상으로 처리한다.

| 동작 | 사진·편집값 | 피격 상태 |
| --- | --- | --- |
| 재배치 / `R` | 유지: 사용자 확정 | 상처·누적 충격을 지우고 기본 사진으로 복귀하는 안을 제안. 미확정 |
| 자동 기립·관절 정렬 | 유지 | 기존 상태 유지 제안 |
| 새 사진 적용 | 새 사진·편집값·변형 사진으로 교체 | 기존 상처·누적 충격 초기화 제안 |
| 편집 취소·파일 선택 취소 | 기존 적용 상태 유지 | 기존 상태 유지 제안 |
| 기본 얼굴로 복귀 | 사용자 사진·관련 메모리 해제 | 초기화 제안 |
| 새로고침·페이지 재진입 | 사진을 복원하지 않음: 사용자 확정 | 기본 캐릭터로 시작 |

‘재배치 시 사진 유지’는 확정이다. 재배치 시 현재 변형 단계와 상처까지 유지할지는 별도 미정 사항이며 위 초기화 안을 임의로 확정하지 않는다.

## 10. 완료 기준과 검증 기록

### 사진·좌표·품질

- [ ] 사진 없이 기본 캐릭터로 플레이할 수 있다.
- [ ] 정면 얼굴 사진을 선택하고 위치·크기·회전을 보정해 적용할 수 있다.
- [ ] 하얀색 안내 마스크 안의 범위만 출력되며 흰 배경이 사진에 합성되지 않는다.
- [ ] 기본 도형의 눈·입이나 별도 표정 그림이 사용자 사진 위에 나타나지 않는다.
- [ ] 특징점이 분석용 축소·편집·자르기 이후에도 같은 얼굴 위치에 맞는다.
- [ ] 큰 편집 미리보기와 실제 게임 표시에서 화질을 비교하고 선택한 출력 해상도·형식·상한을 기록한다.
- [ ] 회전·충돌·관절 정렬·기립·화면 크기 변경에서 사진이 머리에 맞는다.

### 변형·충격·상처

- [ ] 특징점에서 생성한 변형 사진을 충격 조건에 따라 교체할 수 있다.
- [ ] 교체 시 크기·중심·마스크가 바뀌거나 경계가 찢어지지 않는다.
- [ ] 투명 상처 에셋을 얼굴·몸에 적용하고 회전·이동 후에도 위치를 유지한다.
- [ ] 사진 교체 후에도 상처 레이어가 유지된다.
- [ ] 미세 접촉·물리 하위 스텝·자세 보정을 중복 충격으로 누적하지 않는다.
- [ ] 특징점 검출·변형 생성 실패 시 기본 사진 또는 기본 캐릭터로 계속할 수 있다.

### 수명주기·통합

- [ ] 재배치 후 사진·편집값이 유지되고 새 머리에 연결된다.
- [ ] 새로고침 후 사용자 사진·특징점·변형 사진을 복원하지 않는다.
- [ ] 사진 재선택·재편집·취소·기본 얼굴 복귀가 정상 동작한다.
- [ ] 이전 분석 결과가 새 사진을 덮어쓰지 않는다.
- [ ] 편집·파일 선택·창 전환 전후 잡기와 일시정지 상태가 정상이다.
- [ ] 반복 사용 후 텍스처·이미지·이벤트·상처 개수가 무제한 증가하지 않는다.
- [ ] 기준 PC·브라우저·화면 크기·분석 및 변형 준비 시간·플레이 FPS를 기록한다.
- [ ] 1단계 채택 방식의 잡기·던지기·충돌·정렬·기립에 새 문제가 없는지 확인한다.

현재 채택한 2번 버전의 전체 물리 검증은 별도로 관리한다. 실험 1의 과거 25개 통과 기록을 현재 버전의 통과 결과로 사용하지 않는다. 이번 사진 기능의 타입 검사·빌드·24개 브라우저 검사와 실제 모델 확인 결과는 [STAGE_2_PROGRESS.md](STAGE_2_PROGRESS.md)에 기록한다. 아래 미정 항목의 초기 구현값은 사용자 확정 사항과 구분한다. 이 문서의 완료 체크 목록은 사용자 최종 평가까지 포함하므로 일괄 완료 처리하지 않는다.
