# Sites 배포 가능성 확인

확인일: 2026-11-18. 요청 범위는 **가능성 확인만**이며 사이트 생성·소스 업로드·버전 저장·배포·공개 URL 생성은 실행하지 않았습니다.

## 판단

**현재 프로젝트는 Sites의 정적 사이트 형식으로 배포 가능한 구조입니다.** Sites 플러그인 연결의 읽기 요청이 성공했고, 설치된 Sites 스킬의 정적 호스팅 조건과 실제 빌드 결과를 대조했습니다. 이 판단은 구조·로컬 빌드 검증이며 Sites 원격 배포 성공을 의미하지 않습니다.

| 확인 항목 | 결과 |
| --- | --- |
| Sites 연결 | `list_sites` 읽기 요청 성공. 사이트 생성 없음 |
| 빌드 | `npm run build` 성공, `dist/index.html`과 연결 자산 생성 |
| 호스팅 형식 | Sites가 지원하는 `static.directory: dist`에 해당 |
| 서버 필요 여부 | 게임·사진 편집·얼굴 분석·오디오 모두 브라우저 실행. API·DB·Worker 불필요 |
| 사진 목록 | 빌드에서 `images/catalog.json` 생성, 사진 6개 정상 읽기 |
| 정적 실행 | Vite preview로 빌드 결과만 제공한 Chromium 검사에서 게임 로딩·무기 생성·사진 편집창 확인 |
| 모델·WASM | 같은 호스트에서 HTTP 200. WASM의 `application/wasm` 확인, 실제 얼굴 검출 성공 |
| 기타 자산 | 무기·이펙트·사운드 JSON, 모델, 목록의 모든 이미지 HTTP 200 |
| 일반 접속 | `window.__physicsLab` 미노출, 선택적 로컬 저장 버튼 없음 |

## 실제 배포 때 필요한 작업

현재는 `.openai/hosting.json`과 Sites 프로젝트 ID가 없습니다. 배포 요청을 받은 뒤 Sites를 한 번 등록하고 반환된 실제 ID와 `static.directory: dist`를 소스 매니페스트에 기록해야 합니다. 그 소스 상태를 빌드·패키징·동기화한 뒤 버전을 저장하고 배포하는 절차가 남아 있습니다. 이번 확인에서는 이 절차를 실행하지 않았습니다.

`dist/`만으로 게임이 동작하며 루트 기준 자산 경로를 사용합니다. 별도 DB·런타임 비밀값·로그인 연결은 필요하지 않습니다. 모델·WASM·글꼴·음원·이미지를 빌드와 함께 제공해야 합니다.

## 배포 환경에서의 차이와 확인 한계

프로젝트 폴더에 이미지를 쓰는 `.local/image-save/`는 개발 서버의 선택적 확장입니다. 저장 버튼/API는 정적 사이트에 포함되지 않습니다. 브라우저의 새 사진 선택·편집·적용과 빌드에 포함된 사진 목록은 계속 사용할 수 있습니다. 목록에 새 이미지를 추가할 때는 다시 빌드해야 합니다.

빌드 전체는 약 25MiB이며 얼굴 분석 WASM 원본은 약 14.6MB, 메인 JS는 약 1.36MB입니다. Vite의 큰 청크 경고가 있으나 빌드는 성공했습니다. 얼굴 SDK는 사진 선택 때 동적으로 로딩하며, 실제 다운로드 시간과 브라우저 성능은 접속 환경에 따라 달라집니다.

원격 Sites의 업로드 한도·응답 헤더·접근 정책·실제 접속 성능·최종 배포 URL은 확인하지 않았습니다. Chromium에서 정적 실행과 실제 얼굴 검출을 확인했으며 다른 브라우저·모바일의 최종 공개 검증은 후속 범위입니다.
