# 사운드 설정: sounds.json

설정 파일은 이 문서와 같은 폴더의 [sounds.json](sounds.json)이며, 무기·탄알·이펙트 설정은 [설정 안내](README.md)를 참고한다. 음원 파일은 `public/assets/audio/`에 둔다.

일반 타격음은 `collision.normal`, 벽·바닥 충돌음은 `collision.wall`로 통일한다. 충돌 효과음에 약·중·강 등급은 없다. 다른 인형·잔해와의 접촉은 일반음만, 왼쪽·오른쪽·위쪽 벽과 바닥 접촉은 일반음과 벽음을 함께 재생한다. 각 소리의 속도 구간·음량·쿨다운은 독립적이다. 사망 분리음 `death.burst`는 유지한다.

## 설정 위치와 파일

`public/config/sounds.json`을 저장한 뒤 새로고침하면 읽는다. 2026-11-18 설정과 안내를 `public/assets/audio/`에서 이 폴더로 옮겼으며, 사용자 JSON의 내용과 음원 위치는 보존했다. `basePath`는 설정 JSON의 위치가 아닌 배포 사이트의 시작 경로를 기준으로 한다. 따라서 기존 `"basePath": "assets/audio/"`와 `"files": ["sfx/others/BOOM.mp3"]`는 계속 `public/assets/audio/sfx/others/BOOM.mp3`를 읽는다. 런타임은 JSON을 생성·수정하지 않는다.

2026-11-17에 기존 3등급 설정을 일반음·벽음으로 통합했을 때의 최초 조율값은 다음과 같다. 현재 사용자 JSON의 실제 값과는 다를 수 있다.

| 이벤트 | speed (px/s) | sound-size (배수) | cooldownMs |
| --- | --- | --- | --- |
| `collision.normal` | `[0, 2400]` | `[0.01, 0.5]` | 2 |
| `collision.wall` | `[0, 2400]` | `[0.1, 1]` | 10 |

JSON이 없거나 잘못되면 `src/audio/SoundConfig.ts` 기본값을 사용한다. 기본 후보는 일반음 M4A 1개·벽음 OGG 5개·분리 OGG 2개다. 선택한 파일만 내려받아 공유 오디오 버퍼로 보관하며, 같은 파일이 여러 이벤트에 있어도 한 번만 디코딩한다. MP3·M4A도 OGG와 같은 경로로 처리하며 브라우저가 해당 코덱을 디코딩할 수 있어야 한다. 업로드된 MP3 두 파일은 Chromium 디코딩·실제 신호 출력을 확인했다.

## JSON 필드

| 필드 | 규칙 |
| --- | --- |
| `version` | `1` |
| `basePath` | 배포 경로 기준 상대 디렉터리. 예: `assets/audio/`. `public/`이나 맨 앞 `/`는 넣지 않는다 |
| `masterVolume` | 전체 음량 배율 0~1, 기본 0.8 |
| `maxConcurrentSounds` | 전체 동시 재생 수 1~32, 기본 8 |
| `defaults` | 공통 `volume`, `rateRange`, `cooldownMs`, `maxVoices`, `priority`. 이벤트 값이 우선 |
| `events` | `collision.normal`, `collision.wall`, `death.burst`, `weapon.<무기ID>.<신호>`를 사용한다. 충돌·무기 이벤트는 단일 객체 또는 여러 속도 구간의 객체 배열 |
| `events.*.files` | 비어 있지 않은 상대 파일 경로 목록. `basePath` 뒤에 붙인다 |
| `events.collision.*.speed` | 각 설정에 필수인 `[최소 속도, 최대 속도]`, px/s. 유한한 0 이상의 값이며 최대 > 최소. 최솟값 포함·최댓값 제외. 같은 이벤트 안의 구간 중복은 오류, 빈 구간은 무음 |
| `events.collision.*.sound-size` | 필수 `[최소 음량 배수, 최대 음량 배수]`. 유한한 0 이상의 값이며 최대 ≥ 최소. 1을 넘는 배수도 가능 |
| `volume` | 기본 음량 0~1, 생략 시 0.6. 속도에 따른 배수를 추가로 곱한다 |
| `rateRange` | `[최소, 최대]` 재생 속도. 0.25~4이며 최대 ≥ 최소. 기본 `[0.96, 1.04]` |
| `cooldownMs` | 0 이상의 유한한 재생 간격(ms). 각 구간 설정 → defaults → 0 순서로 적용. 0이면 제한 없음. 배열의 구간별로 독립 적용 |
| `maxVoices` | 구간별 동시 재생 수 1~32, 기본 2. 단일 객체는 해당 이벤트 전체에 적용 |
| `priority` | 교체 우선순위 0~100, 기본 1. 큰 값이 우선 |
| `debris.volumeScale` | 잔해를 포함한 충돌의 음량 배율 0~1, 기본 0.35. 분리음에는 적용하지 않는다 |

충돌 이벤트에는 `speed`와 `sound-size`가 필수다. `death.burst`는 기존 `volume`으로 재생한다. 예전 `collision.light/medium/heavy`, `collision.wall.light/medium/heavy`, `collision.floor.*` 키는 새 형식으로 바꿔야 한다.

무기 신호 `weapon.bat.hit/finish`, `weapon.hammer.hit/finish`, `weapon.gun.fire/hit/finish/pin/burst`도 지원한다. 무기의 단일 설정에서 `speed`·`sound-size`를 함께 생략하면 고정 음량이고, 함께 지정하거나 배열로 작성하면 기존과 같은 속도별 음량/구간 선택을 사용한다. 전용 설정이 없으면 초기 시제품은 기존 일반음·벽음·분리음의 첫 설정에서 파일·기본 음량·쿨다운을 임시 재사용한다. 임시 연결에는 충돌 전용 속도 구간을 적용하지 않으며 재생 기록은 신호별로 분리한다. 자세한 신호와 연결은 [무기 안내](../../WEAPONS_AND_EFFECTS.md)를 참고한다. 사용자 사운드 JSON에 자동으로 키를 추가하지 않는다.

## 무기 타격 사운드 추가

1. 음원을 `public/assets/audio/sfx/` 아래에 둔다. 예를 들어 `public/assets/audio/sfx/others/hard-punch.mp3`를 사용한다.
2. `weapons.json`에서 해당 무기의 `signals.hit` 이름을 확인한다. 기본 방망이는 `weapon.bat.hit`, 망치는 `weapon.hammer.hit`, 총알 명중은 `weapon.gun.hit`이다.
3. `sounds.json`의 기존 `events` 객체 안에 같은 이름의 항목을 추가한다. 아래는 기존 파일을 사용하는 방망이 타격음 예시이며, 다른 이벤트 항목은 보존한다.

```json
"weapon.bat.hit": {
  "files": ["sfx/others/hard-punch.mp3"],
  "volume": 0.8,
  "rateRange": [0.96, 1.04],
  "cooldownMs": 0,
  "maxVoices": 6,
  "priority": 5
}
```

위 항목은 `events` 내부에 넣는 조각이다. 앞뒤 항목 사이에 쉼표를 넣고 같은 키를 중복 작성하지 않는다. 이 예시는 안내에만 있으며 실제 `sounds.json`에는 자동 추가하지 않았다. 저장 후 새로고침하고 화면을 한 번 클릭하면 음원이 준비되어 재생된다.

| 이벤트 이름 | 재생 시점 |
| --- | --- |
| `weapon.bat.hit` / `weapon.hammer.hit` | 해당 무기의 유효 타격 |
| `weapon.gun.hit` | 탄알이 랙돌 또는 허용된 잔해에 명중 |
| `weapon.gun.fire` | 총에서 발사 |
| `weapon.bat.finish` / `weapon.hammer.finish` / `weapon.gun.finish` | 해당 무기로 실제 HP가 0이 된 마지막 타격 |
| `weapon.gun.pin` | 마지막 타격 연출에서 벽에 고정 |
| `weapon.gun.burst` | 벽 고정 뒤 폭발 |

망치에는 같은 방식으로 `weapon.hammer.hit`를 추가하고 파일을 바꾼다. 총의 타격음은 `weapon.gun.hit`, 발사음은 `weapon.gun.fire`에 각각 설정한다. `signals` 이름을 바꿨다면 사운드와 이펙트의 `events` 키도 동일하게 맞춘다. `sounds.json`은 소리, `effects.json`은 같은 신호의 화면 효과를 담당한다.

`cooldownMs: 0`은 해당 사운드의 재생 간격을 없애며, HP의 피격 무적시간은 바꾸지 않는다. 생략하면 현재 사용자 파일의 `defaults.cooldownMs`인 **1000ms**를 상속하므로 빠른 연속 타격음이 생략될 수 있다. 이 값은 사용자가 바꿀 수 있다. 서로 다른 총에서 발생한 같은 신호도 해당 이벤트의 쿨다운과 `maxVoices`를 공유하며, 전체 재생 수는 `maxConcurrentSounds`로 제한한다.

`speed`와 `sound-size`를 둘 다 생략한 위 예시는 속도 구간에 의해 무음이 되지 않는다. 속도별로 소리를 구분하고 싶으면 두 필드를 함께 추가하거나, 아래 충돌음 예시처럼 객체 배열을 사용한다. 무기 신호의 속도는 방망이·망치의 타격 판정 속도 또는 탄알의 `projectile.speed`이며, 일반 충돌음의 충돌 직후 상대 속력과는 측정 기준이 다르다.

명중 신호는 HP 감소 여부와 별개로 발생한다. 무적 중에도 유효한 무기 타격은 소리를 요청하지만, 마지막 타격 신호는 실제 사망한 경우에만 발생한다. 신호가 없거나 구간 밖·쿨다운·재생 상한·음소거·파일 누락으로 재생되지 않는지 구분해서 확인한다.

## 여러 속도 구간

같은 JSON 키를 반복하지 않고 `collision.normal` 또는 `collision.wall` 값에 설정 배열을 넣는다. 기존 단일 객체 형식도 계속 지원한다. 다음은 `events` 안에 넣는 작성 예시이며 실제 JSON은 사용자가 편집한다. 예시 파일명은 사용할 음원 경로로 바꾼다.

```json
"collision.normal": [
  {
    "files": ["sfx/weak.ogg"],
    "speed": [300, 1000],
    "sound-size": [0.1, 1],
    "cooldownMs": 0
  },
  {
    "files": ["sfx/strong.ogg"],
    "speed": [1000, 2400],
    "sound-size": [0.5, 2],
    "cooldownMs": 0
  }
]
```

700px/s는 첫 구간, 정확히 1000px/s와 1700px/s는 둘째 구간을 선택한다. 2400px/s는 마지막 구간의 상한이므로 무음이다. 배열 순서는 자유이며 같은 이벤트의 구간끼리 겹치거나 배열이 비면 설정 오류다. 서로 다른 이벤트인 일반음·벽음의 구간은 겹쳐도 된다. 벽 충돌에서는 각 이벤트가 속도에 맞는 구간을 하나씩 선택해 함께 재생한다. `death.burst`는 배열을 지원하지 않는다.

각 구간은 자체 파일 후보·음량 배수·쿨다운·재생 수·우선순위를 가지며 생략 가능한 재생 설정은 `defaults`를 따른다. 모든 구간의 음원을 미리 로딩하고 같은 파일은 한 번만 내려받아 디코딩한다.

## 속도와 음량의 대응

속도 `v`, `speed: [a, b]`, `sound-size: [c, d]`일 때 구간 안의 음량 배수는 다음과 같다.

`c + (d - c) × (v - a) / (b - a)`

예를 들어 `speed: [100, 1000]`, `sound-size: [0.1, 0.8]`이면 100px/s에서 0.1배, 550px/s에서 0.45배, 1000px/s에 가까워질수록 0.8배에 가까워진다. 정확히 1000px/s는 해당 구간에 포함하지 않는다. 최종 음량은 `이벤트 volume × 속도 배수 × 잔해 배수 × masterVolume × UI 음량`이다. 속도 구간 밖·정지·유효하지 않은 속도는 무음이며, 구간 밖 요청은 쿨다운을 소비하지 않는다.

측정값은 **충돌 처리 직후 접촉점의 상대 속력**이다. 신체의 선속도와 접촉점 회전 속도를 합치고 상대 신체의 움직임을 뺀 뒤 크기를 사용한다. 모든 인형을 물리 엔진 처리 직후에 측정하며 자세 보정·손상 반응·잔해 속도 제한은 그다음이다. 엔진의 60Hz 기준 속도를 px/s로 환산하므로 적응 하위 스텝 크기에 영향을 받지 않는다.

HP는 기존 충돌 전 접근 속도·800px/s 기준·300ms 무적·잔해 손상 보정을 유지한다. 효과음은 HP 피해량과 별개로 JSON의 속도 조건만 따른다. 따라서 HP가 줄지 않는 충돌도 설정 구간 안이면 재생한다. 생성 보호 중 기립 착지·외형 미리보기·자세 보정은 충돌음을 만들지 않는다.

## 쿨다운·재생 수·정리

- 같은 속도 구간의 쿨다운은 모든 랙돌과 해당 구간의 음원 후보가 공유한다. 배열의 다른 구간·일반음·벽음·사망음은 각각 독립적이다. 실제 재생 성공 시점부터 물리 시간으로 계산하며 정확히 지정 간격부터 재생할 수 있다.
- 쿨다운 중 요청은 생략하고 대기열에 남기거나 쿨다운을 연장하지 않는다. 음원 누락·무음·잠금으로 재생하지 못해도 쿨다운을 시작하지 않는다.
- 한쪽 소리의 범위 밖·무음·파일 로딩 실패·쿨다운은 다른 소리를 막지 않는다. 후보가 여러 개면 직전 파일을 피한다.
- 같은 접촉 시작의 양쪽 보고와 여러 접촉점은 한 요청으로 합친다. 지속 접촉 중 매 물리 스텝마다 반복 재생하지 않으며 실제 비접촉 후 재충돌은 새 요청이다.
- 전체·이벤트 상한에서는 기존 소리를 교체한다. 한 충돌의 두 소리가 서로 끊지 않도록 기존 소리를 먼저 교체한다. 전체 상한이 1이면 한 소리만 유지한다.
- 첫 클릭/키 입력 후 소리가 활성화된다. 준비 전 요청은 나중에 몰아서 재생하지 않는다. 음량·음소거는 로컬에 저장한다.
- 일시정지·창 비활성화·사진 편집은 재생과 대기열을 비우되 쿨다운은 유지한다. R은 쿨다운도 초기화하고 버퍼는 재사용한다. 장면 종료에서 입력·요청·버퍼·노드를 해제한다.

## 실패와 라이선스

설정 오류는 콘솔에 원인을 표시하고 기본 설정으로 진행한다. 개별 파일 누락은 해당 이벤트의 남은 후보만 사용하며 다른 이벤트로 바꾸지 않는다. 모든 파일 또는 Web Audio를 사용할 수 없으면 게임을 소리 없이 계속한다. Kenney Impact Sounds는 CC0이며 `public/assets/audio/sfx/kenney-impact/License.txt`를 보존한다. 다른 팩은 해당 라이선스를 확인한다. Kenney 원본 출처: https://kenney.nl/assets/impact-sounds

## 검증

`npx playwright test tests/sound-rules.spec.ts tests/sound.spec.ts`

규칙 19개·Chromium 15개를 검증한다. 무기 신호·임시 음원 재사용·독립 쿨다운, 단일 설정과 배열 구간·경계·중복 거부·빈 구간·구간별 재생 수·음원 로딩/중복 제거·음량 보간·배수·설정 오류, 충돌 후 속도와 충돌 전 HP 속도의 분리, 상대 회전·하위 스텝 단위, 네 면의 실제 일반음/벽음 재생, HP 손상 없는 접촉·무적, 쿨다운 0/양수·초기화·개별 실패, 동시 재생 한도·잔해·음량 저장·수명주기를 포함한다. 브라우저 검사는 사용자 음원 변경과 독립적으로 실제 OGG 샘플을 테스트 응답으로 사용한다.
